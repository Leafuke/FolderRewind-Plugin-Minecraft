# MineRewind 读取与增量诊断约束

本规范约束只读展示、导航、玩家保留和 `minecraft-world-incremental` v1 的诊断缓存。原始文件 recipe、区块内容指纹、合并策略与恢复授权不由本规范变更。

## 读取预算

展示和导航的 NBT 压缩输入、解压输出分别限制为 16 MiB；玩家保留分别为 64 MiB。两类配置都先做完整结构验证，再投影字段：深度不超过 64、标签不超过 100,000、单个数组／列表长度不超过 1,048,576。读取、结构验证和对象解析均检查取消。玩家保留另保留最多 4,096 个提案、总提案 64 MiB 的限制。

每次目录扫描累计最多 100,000 个目录项、相对路径累计 4 MiB、深度 64。空目录与不匹配文件同样计数；自定义维度继续限制为 16 层。固定历史输入拒绝链接；展示和发现跳过子项链接并返回不完整诊断。扫描或权限错误不得扩大世界管理边界，也不得改变恢复协调使用的世界识别结果。

Host 在调用前冻结配置快照，并在后台调用元数据能力。详情先显示基础字段，再异步补充插件字段；取消或加载修订变化后不得提交迟到结果。区域统计未完成时显示“至少 N／统计未完成”。多世界来源只显示集合信息。版本元数据只从 Host 提供的受控流读取内容。

## 增量 state 的可选字段

Artifact format 和 state `Version` 保持 1。根对象增加可选 `SemanticClassifierVersion`（当前 1）与 `WorldRootsFingerprint`（排序后的世界根集合 JSON 的 SHA-256）。每个 `.mca` 文件可增加 `SemanticSummary`：

| 字段 | 含义／范围 |
|---|---|
| ClassifierVersion | 当前为 1 |
| OpaqueRegions | 无法完整分类的 region，0 或 1 |
| CorruptChunks | 损坏 chunk 数，0–1024 |
| UnsupportedChunks | 不支持的 chunk 数，0–1024 |
| MissingExternalFiles | 缺失外置文件数，0–1024 |
| UnclassifiedRegions | 没有匹配世界布局的 region，0 或 1 |

旧读取者可以忽略新增字段；新读取者可以读取没有这些字段的旧 v1。缺失、未知版本或无效摘要不能解释为健康。首次从已有索引补齐后，未变文件沿用摘要，不重复读取索引或 payload。世界根或分类版本变化时重建受影响索引，保留原始 recipe；删除文件同时删除摘要。仅 `.mcc` 改变时刷新其 owner 的索引和摘要，修复后移除对应警告。

摘要只聚合诊断，不参与完整性验证、删除判定或恢复授权。Full 与增量都对有限语义覆盖给出警告，同时保留原始字节。NoChanges 不重写既有 Version；没有重新检查的内容不能宣称健康，也不能清除既有历史诊断。新增 state 在交给 staging 前检查 64 MiB 上限。
